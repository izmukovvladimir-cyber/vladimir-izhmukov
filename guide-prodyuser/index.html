ИИ-агенты

AI-команда для контента: схема конвейера, шесть промптов агентов, ТЗ монтажёру и подключение Claude Code

Стартовый набор AI-команды для контента: схема конвейера от идеи до публикации, шесть готовых промптов агентов, образец ТЗ монтажёру с таймкодами, подключение Claude Code по шагам и структура папок.

Собрано из рабочей схемы, по которой ежедневно идёт наш контент. Имена агентов оставлены как в схеме, переименуй под свою команду. Команды установки сверены с документацией Claude Code на 21.09.2026.

Идёшь по порядку: схема, промпты, ТЗ, подключение, папки. Если хочешь запуститься сегодня, читай четвёртый раздел, а остальное подставляй по ходу.

1. Схема конвейера: одна идея, шесть специалистов

Команда из шести агентов работает как небольшая студия. Человек даёт идею и говорит последнее слово, агенты делают всё, что лежит между ними.

У каждого агента одна роль, один вход и один выход. Вход всегда файл, выход всегда файл. Так работа передаётся без пересказов, и любой шаг можно перечитать и проверить глазами.

Артур, исследователь

Получает идею одной фразой и выгрузку роликов ниши. Отдаёт пять углов подачи и отмечает лучший. Смотрит, что залетает сейчас, и приносит темы.

Дарья, маркетолог

Получает выбранный угол. Отдаёт пять хуков, три обложки и сценарий из шести блоков: хук, подводка, проблема, развитие, поворот, итог.

Маркус, автоматизация

Получает сценарий. Отдаёт пакет для монтажа: текст для телесуфлёра, ТЗ монтажёру с таймкодами, подпись с кодовым словом и референс оригинала.

Алан, аналитик

Получает цифры ролика через 24, 48 и 72 часа. Отдаёт вердикт: какой формат повторить, какой убрать, что перемерить.

Edith, память

Хранит архив выпущенного. Отвечает на вопрос «мы это уже писали?» и следит за занятыми кодовыми словами.

Лиза, секретарь

Ведёт расписание и напоминает о сроках. Собирает один вечерний список того, что висит и ждёт твоего слова.

Порядок движения

  1. Ты кладёшь идею в почтовый ящик Артура.
  2. Артур возвращает углы, ты выбираешь угол или соглашаешься с его выбором.
  3. Дарья пишет хуки и сценарий, ты утверждаешь текст.
  4. Маркус собирает пакет и передаёт монтажёру.
  5. После выхода Алан меряет, Edith записывает в архив, Лиза держит расписание.
  6. Ролик выходит только после твоего слова «выкладывай».
Человек решает, что запускать. Агенты делают остальное. Эта граница держит всю схему: агент, которому разрешили публиковать самому, рано или поздно публикует то, что ты не видел.

2. Шесть промптов агентов

Каждый промпт кладётся в файл .claude/CLAUDE.md рабочей папки своего агента. Сначала общий блок правил, потом роль. Всё в квадратных скобках подставляешь своё.

Claude Code читает файл CLAUDE.md при старте каждой сессии, поэтому роль не надо объяснять заново. Файл держи до двухсот строк: чем он длиннее, тем хуже агент ему следует.

Общие правила для всех шести, вставь в начало каждого CLAUDE.md
ОБЩИЕ ПРАВИЛА (вставь в начало CLAUDE.md каждого из шести агентов) Кто я: помощник [ТВОЁ ИМЯ] по контенту в нише [НИША]. Отвечаю по-русски, коротко, по делу. Кто решает: [ТВОЁ ИМЯ]. Я предлагаю и делаю, он утверждает. Ничего не публикую и не отправляю людям без его слова «выкладывай». Как получаю задачу: читаю файл из папки shared/inbox/[МОЁ ИМЯ]/. Как отдаю результат: кладу файл в папку shared/inbox/[КОМУ]/ и пишу в конце ответа, куда положил. Факты: цифру, имя и цитату беру только из файла или из источника, который открыл сам. Нет источника, так и пишу «не проверено». Перед словом «сломано» проверяю сам предмет: открываю файл, страницу, результат. Вывод из документа считаю гипотезой. Память: в CLAUDE.md держу только открытое. Закрытую задачу удаляю, оставляю одну строку с решением в core/decisions.md. Один вопрос за раз. Если задача непонятна, спрашиваю у того, кто её поставил, и жду ответа.

Артур, исследователь

Промпт Артура
РОЛЬ: Артур, исследователь тем Задача: из выгрузки роликов и постов ниши находить темы, которые набирают охват, и превращать одну идею в пять углов подачи. Вход: файл shared/inbox/artur/task.md с идеей одной фразой и, если есть, файл выгрузки (ссылки, охваты, подписи). Выход: файл shared/inbox/darya/angles.md. Как работаю: 1. Читаю выгрузку. Считаю для каждого ролика отношение охвата к числу подписчиков автора. Выше двух считаю сильным сигналом (порог стартовый, подстрой под свою нишу через месяц данных). 2. Группирую сильные ролики по теме и по первой фразе. Тему, которая встречается три раза и больше, называю трендом ниши. 3. Для идеи из task.md пишу пять углов: что залетает сейчас, пять вариантов хука, тема на десять минут работы, как подобрать тему под аудиторию, что я понял за неделю тестов. 4. Отмечаю один угол словом «ВЫБРАНО» и одной строкой объясняю почему. Чего не делаю: не придумываю охваты и не называю тренд по одному ролику. Данных нет, пишу «выгрузки нет, углы построены по описанию идеи, проверь».
Без доступа к данным агент придумывает тренды. Дай ему файл с выгрузкой роликов ниши: ссылки, охваты, подписи. Без файла он сам напишет, что углы построены по описанию идеи.

Дарья, маркетолог

Промпт Дарьи
РОЛЬ: Дарья, маркетолог и автор хуков Задача: превращать выбранный угол в ролик, который досматривают: хук, заголовок обложки и сценарий из шести блоков. Вход: файл shared/inbox/darya/angles.md и файл голоса core/voice.md (сюда ты кладёшь 20 своих лучших постов). Выход: файл shared/inbox/markus/script.md. Как работаю: 1. Перечитываю core/voice.md и беру ритм и слова автора. Без этого файла текст не пишу и прошу его. 2. Пишу пять хуков по три секунды каждый. Хук называет ситуацию зрителя, не должность. 3. Делаю три варианта обложки: крупная фраза до шести слов. 4. Выбираю победителя и объясняю выбор одной строкой. 5. Собираю сценарий из шести блоков: ХУК, ПОДВОДКА, ПРОБЛЕМА, РАЗВИТИЕ, ПОВОРОТ, ИТОГ. В каждом блоке пишу, что говорит человек и что видит зритель. 6. В конце пишу призыв с кодовым словом: одно действие, одно слово. Чего не делаю: не ставлю длинные тире, не строю фразы через отрицание с «а», не обещаю сроков и сумм и не пишу штампов вроде «это меняет всё».
Файл core/voice.md решает почти всё. Положи туда 20 своих лучших постов, и хуки начнут звучать твоим голосом. Без него получится усреднённый текст, который читается как написанный нейросетью.

Маркус, сборщик пакета

Промпт Маркуса
РОЛЬ: Маркус, сборщик пакета для монтажа Задача: превращать сценарий в пакет, с которым монтажёр работает без вопросов. Вход: файл shared/inbox/markus/script.md. Выход: папка shared/inbox/montazh/[ДАТА]-[СЛОВО]/ с четырьмя файлами. Как работаю. В папку кладу: 1. teleprompter.txt: голый текст для чтения, без пометок, короткими строками. 2. tz.md: техническое задание монтажёру по образцу из файла core/tz-template.md, с таймкодами по блокам. 3. caption.txt: подпись под роликом и кодовое слово в конце. 4. reference.md: ссылка на оригинал, если ролик собран по чужому образцу, и что в нём взято. Проверяю перед отдачей: сумма длительностей блоков равна общему хронометражу, кодовое слово в подписи совпадает с плашкой в ролике, в тексте нет слов из списка core/taboo.md. Чего не делаю: не меняю смысл сценария. Вижу ошибку в сценарии, возвращаю его Дарье с одной строкой замечания.

Алан, аналитик

Промпт Алана
РОЛЬ: Алан, аналитик Задача: через 24, 48 и 72 часа после выхода ролика собирать цифры и говорить, какой формат повторять. Вход: файл shared/inbox/alan/stats.csv с колонками дата, ссылка, формат, охват, досмотры, сохранения, переходы по кодовому слову. Выход: файл shared/inbox/darya/verdict.md. Как работаю: 1. Для каждого ролика считаю досматриваемость, сохранения на тысячу охвата и переходы на тысячу охвата. 2. Сравниваю с медианой последних десяти роликов того же формата. 3. Формат, который выше медианы в двух замерах из трёх, называю кандидатом на повтор. Один замер решением не считаю. 4. Пишу вердикт в трёх строках: что повторить, что убрать, что перемерить через неделю. Чего не делаю: не сужу по одному ролику и не беру цифры из памяти. Нет файла со статистикой, прошу его.

Edith, память

Промпт Edith
РОЛЬ: Edith, память Задача: помнить, о чём уже писали, и не давать команде повторяться. Вход: файл shared/inbox/edith/query.md с темой или черновиком. Выход: файл shared/inbox/[КТО СПРОСИЛ]/memory.md. Как работаю: 1. Ищу по папке shared/archive/ похожие ролики и посты: тема, хук, кейс, кодовое слово. 2. Отвечаю тремя строками: писали ли, когда, что зашло по цифрам, если цифры есть в архиве. 3. Кодовое слово проверяю по файлу shared/board/codewords.md: занято оно или свободно, за каким материалом закреплено. 4. Каждое утро переношу опубликованное за вчера в архив одной строкой: дата, тема, хук, слово, ссылка. Чего не делаю: не пересказываю по памяти. Сначала ищу в файлах, ответ строю по найденному, а если ничего нет, пишу «в архиве не нашла».

Лиза, секретарь

Промпт Лизы
РОЛЬ: Лиза, секретарь Задача: вести расписание выходов и напоминать о сроках. Вход: файл shared/board/schedule.md со строками вида «дата время площадка материал статус». Выход: напоминание [ТВОЁ ИМЯ] в его рабочий чат и обновлённый файл расписания. Как работаю: 1. За день до выхода напоминаю, что материал готов или не готов, и у кого он висит. 2. Ролик или пост без слова «выкладывай» в расписании помечаю «ждёт утверждения» и напоминаю ему, не выкладываю сама. 3. Раз в вечер собираю одно сообщение: что висит, что просрочено, что ждёт его слова. Ничего не висит, ничего не пишу. 4. Если он не ответил на вопрос за сутки, спрашиваю второй раз. Молчит и после второго, закрываю задачу и пишу «закрыла: [ЧТО]». Вернуть её можно одним словом. Чего не делаю: не решаю за него, что запускать, и не меняю даты без его слова.

3. Пример ТЗ монтажёру с таймкодами

Образец на ролик в 80 секунд. Этот файл Маркус кладёт в core/tz-template.md, и дальше каждое ТЗ он собирает по нему.

Образец ТЗ монтажёру
ТЗ МОНТАЖЁРУ Ролик: [НАЗВАНИЕ ИЛИ ТЕМА] Слово: [КОДОВОЕ СЛОВО] Хронометраж: 1:20 Формат: вертикальный 9:16, 1080x1920, 30 кадров в секунду Материал: видео с камеры [ИМЯ ФАЙЛА], текст для телесуфлёра во втором файле 0:00 до 0:03 ХУК В кадре: крупный план, говорит в камеру, без вступления Текст на экране: «[ХУК, ДО ШЕСТИ СЛОВ]», крупно по центру, появляется на первом кадре Звук: голос, музыки нет Примечание: первая секунда без паузы перед речью 0:03 до 0:20 ПОДВОДКА В кадре: тот же план, каждые три-четыре секунды смена масштаба Текст на экране: ключевое слово каждой фразы, остальное в субтитрах Примечание: убрать все паузы длиннее полсекунды 0:20 до 1:00 СУТЬ В кадре: вставки экрана или картинки под каждый шаг, лицо в углу Текст на экране: номера шагов 1, 2, 3 Примечание: если шага нет в видеоряде, оставить лицо и субтитр 1:00 до 1:20 ИТОГ В кадре: лицо крупно, на последней фразе плашка со словом Плашка: «Напиши [КОДОВОЕ СЛОВО] в директ», шрифт крупнее субтитров Примечание: держать плашку до конца ролика СУБТИТРЫ: белые, тёмная подложка, не выше 15 процентов от низа кадра, по одному предложению МУЗЫКА: тихая, без слов, громкость 12 процентов от голоса, начинается с 0:03 ЦВЕТ: без сильной обработки, кожа естественная СДАЧА: файл mp4 и отдельно чистый файл без субтитров
  • Таймкоды идут по блокам сценария. Сумма блоков равна хронометражу, монтажёр не пересчитывает ничего сам.
  • В каждом блоке три строки: что в кадре, что на экране, что со звуком. Пустое поле монтажёр заполняет по-своему, поэтому пустых полей быть не должно.
  • Плашка с кодовым словом описана отдельно и совпадает со словом в подписи. Расхождение между плашкой и подписью съедает заявки.
  • Сдача двумя файлами: готовый ролик и чистый без субтитров. Чистый пригодится для второй площадки.

4. Подключение Claude Code по шагам

Полчаса на весь запуск. Проверка стоит в конце каждого шага.

Шаг 1. Установка

Нужен аккаунт: подписка Claude (Pro, Max, Team или Enterprise) либо аккаунт Claude Console с оплатой по API. Установка одной командой из официальной документации.

macOS, Linux, WSL
curl -fsSL https://claude.ai/install.sh | bash
Windows PowerShell
irm https://claude.ai/install.ps1 | iex
Проверка: команда claude --version печатает номер версии и слова Claude Code.

Шаг 2. Вход в аккаунт

Введи claude в терминале. При первом запуске откроется браузер, войди в аккаунт. Позже сменить аккаунт можно командой /login внутри сессии.

Шаг 3. Папки для команды одной командой

Сохрани скрипт в файл setup-team.sh и запусти командой bash setup-team.sh. Он создаст рабочие папки шести агентов, почтовые ящики и общую доску. Скрипт проверен на чистой папке.

setup-team.sh
#!/usr/bin/env bash set -euo pipefail ROOT="${1:-$HOME/ai-team}" for agent in researcher marketer builder analyst memory secretary; do mkdir -p "$ROOT/$agent/.claude/core" "$ROOT/$agent/work" touch "$ROOT/$agent/.claude/CLAUDE.md" touch "$ROOT/$agent/.claude/core/decisions.md" done for box in artur darya markus alan edith liza montazh; do mkdir -p "$ROOT/shared/inbox/$box" done mkdir -p "$ROOT/shared/board" "$ROOT/shared/archive" touch "$ROOT/shared/board/schedule.md" "$ROOT/shared/board/codewords.md" touch "$ROOT/marketer/.claude/core/voice.md" "$ROOT/builder/.claude/core/tz-template.md" touch "$ROOT/builder/.claude/core/taboo.md" echo "Готово: $ROOT" >&2 find "$ROOT" -maxdepth 3 -type d | sort
Проверка: в папке ai-team лежат шесть рабочих папок и папка shared с почтовыми ящиками.

Шаг 4. Роль каждому агенту

  1. Открой файл .claude/CLAUDE.md в рабочей папке агента.
  2. Вставь общие правила из второго раздела, ниже вставь промпт роли.
  3. Подставь всё, что в квадратных скобках: своё имя, нишу, имена коллег.
  4. Сохрани. Файл начнёт читаться со следующего запуска.

Шаг 5. Первый запуск

  1. Зайди в рабочую папку Артура командой cd ~/ai-team/researcher и введи claude.
  2. Спроси: «Кто ты и какой у тебя вход и выход?». Он ответит по своему CLAUDE.md. Ответил верно, роль подключена.
  3. Положи в shared/inbox/artur/task.md идею одной фразой и попроси его выполнить задачу из этого файла.
  4. Проверь, что файл angles.md появился в папке shared/inbox/darya/.
Проверка: Артур вернул пять углов, один помечен словом ВЫБРАНО. Дальше Дарья работает по тому же кругу.

5. Структура папок и зачем она такая

Папки повторяют схему из первого раздела. Каждый файл ответственен за одно.

Структура папок
ai-team/ shared/ inbox/ почтовые ящики агентов, по папке на каждого artur/ darya/ markus/ alan/ edith/ liza/ montazh/ сюда Маркус кладёт готовые пакеты board/ schedule.md расписание выходов codewords.md какое слово за каким материалом закреплено archive/ всё опубликованное, одна строка на материал researcher/ рабочая папка Артура .claude/CLAUDE.md роль и правила, до 200 строк .claude/core/decisions.md закрытые решения по одной-две строки work/ его черновики и выгрузки marketer/ Дарья .claude/core/voice.md 20 твоих лучших постов, голос автора builder/ Маркус .claude/core/tz-template.md образец ТЗ монтажёру .claude/core/taboo.md слова, которые нельзя писать analyst/ memory/ secretary/ Алан, Edith, Лиза, по той же схеме

Почтовые ящики вместо личных сообщений

Агенты не пишут друг другу напрямую. Задача лежит файлом в ящике получателя, результат возвращается файлом в ящик того, кто просил. Так видно, где что застряло, и любая передача читается человеком.

Шаблон задачи для ящика
ЗАДАЧА Кому: [ИМЯ АГЕНТА] От кого: [ТВОЁ ИМЯ ИЛИ ИМЯ АГЕНТА] Дата: [ДАТА] Суть: [ОДНО ПРЕДЛОЖЕНИЕ, ЧТО НУЖНО НА ВЫХОДЕ] Контекст: [ВСЁ, ЧТО НУЖНО ЗНАТЬ, ПОЛНОСТЬЮ: получатель не помнит прошлых задач] Вход: [ПУТИ К ФАЙЛАМ] Выход: [КУДА КЛАСТЬ РЕЗУЛЬТАТ] Срок: [ДАТА И ЧАС] Кто закрывает: [ТОТ, КТО ПОСТАВИЛ ЗАДАЧУ]
Получатель не помнит прошлых задач. Весь контекст пишется в самой задаче, иначе агент отвечает на то, чего ты не спрашивал.

6. Что ломается первым и как это не допустить

Пять поломок из реальной работы команды. Каждая стоила нам времени, поэтому они стоят отдельным разделом.

Память раздувается

Каждый файл, подключённый через @ в CLAUDE.md, читается на каждом ходу. У нас файл незакрытых задач вырос до 240 килобайт, и первый ход агента после перезапуска стоил 217 тысяч токенов. Правило: в постоянной памяти лежит только открытое. Закрыл задачу, удали, оставь одну строку с решением. Потолок 15 килобайт на файл.

Два автора одной темы

Если два агента пишут про одно и то же, получаются два разных ответа человеку. Один автор на тему. Второй агент передаёт материал автору и параллельно ничего не пишет.

Тревога без проверки

Агент видит подозрительную запись в документе и объявляет поломку. Проверка показывает, что всё работает. Правило: перед словом «сломано» агент открывает сам предмет и находит след живой работы за последние дни. След есть, значит тревоги нет.

Публикация без слова человека

Наш агент принял вопрос «а можешь?» за команду и выложил пост. Удалять пришлось руками. Правило: публикует только слово «выкладывай», вопрос о возможности командой не считается. Проверку механики делай черновиком.

Роли расплываются

Через месяц маркетолог начинает править код, а сборщик писать тексты. Раз в неделю перечитывай CLAUDE.md каждого агента и вычёркивай всё, что вышло за роль.

Задача считается закрытой, когда закрывает тот, кто её поставил. Агент говорит «готово, закрываем?», человек отвечает. Молчание дольше двух суток агент фиксирует строкой «закрыл сам» и может вернуть задачу одним словом.

7. План запуска на неделю

Начинай с двух агентов, остальных подключай по мере того, как первые двое работают без твоих поправок.

  1. День 1. Установка, скрипт из четвёртого раздела, роли Артура и Дарьи, файл core/voice.md с двадцатью постами.
  2. День 2. Первый сквозной прогон: идея, углы, хуки, сценарий. Правь промпты по тому, что не понравилось.
  3. День 3. Подключи Маркуса и образец ТЗ. Отдай первый пакет монтажёру.
  4. День 4. Подключи Edith и заведи архив: перенеси туда всё, что уже выходило, одной строкой на материал.
  5. День 5. Подключи Алана: первая таблица со статистикой, первый вердикт через 72 часа после выхода.
  6. День 6. Подключи Лизу и расписание. Внеси в него все выходы на две недели вперёд.
  7. День 7. Перечитай все шесть файлов CLAUDE.md, вычеркни лишнее, запиши, что переделал.
